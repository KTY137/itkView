# itkView v0.2.2

This release brings the itkView desktop application to mainstream Linux
distributions on both `x86_64` and `aarch64`, while preserving the product's
read-only boundary.

## Linux packages

Every supported architecture is published in four formats:

- Flatpak is the distribution-independent desktop package and uses GNOME
  Runtime 50. Its sandbox permits network, display and GPU access, but no
  blanket home- or host-filesystem access.
- AppImage is the portable package for compatible glibc-based desktops.
- DEB targets Debian, Ubuntu, Linux Mint and their derivatives.
- RPM targets Fedora and openSUSE families; RHEL 10 derivatives require EPEL
  10 for WebKitGTK 4.1.

Each architecture has a separate `SHA256SUMS-<arch>` file. The tag workflow
builds on native Ubuntu 22.04 runners, verifies exactly one package of every
format, rechecks the checksums, and publishes all ten files only after both
architectures succeed.

## Reliable desktop shutdown

- The Linux shell first sends `SIGTERM` to the PyInstaller onefile bootstrap
  and waits for a bounded grace period. This lets the backend close normally
  and lets PyInstaller remove its `_MEI*` extraction directory.
- A timeout still falls back to `SIGKILL`.
- The frozen Linux child installs `PR_SET_PDEATHSIG`, so an abruptly killed
  bootstrap cannot leave a headless backend holding its SQLite database and
  localhost port.
- CI exercises graceful shutdown and forced parent death as separate paths.

## Reproducible packaging

- Python 3.12 dependencies, including `itkdb` and PyInstaller, come from the
  locked `backend[desktop]` environment. Missing PDB client code is now a hard
  package failure instead of producing a silently incomplete sidecar.
- Frontend and desktop Node dependencies are installed from their lockfiles.
- DEB and RPM metadata is checked for the WebKitGTK 4.1 and GTK 3 runtime
  dependencies before upload.
- A release is created as a draft, receives only checksum-verified assets, and
  is published only after every upload succeeds.

## Read-only boundary

Unchanged: itkView can mirror production data after the user supplies personal
access codes, but it cannot author tests, move stages, assemble components or
write to the PDB. The packaged sidecar reports `product_variant=view`,
`write_features_enabled=false` and `pdb_write_scope=disabled`.

## Compatibility limits

- The current Ubuntu 22.04 AppImage payload can require glibc 2.35. It is not
  advertised for RHEL 9; use the Flatpak there.
- Alpine/musl, NixOS, Guix, AUR/Snap ecosystems and 32-bit systems have no
  first-party native package in this release. Flatpak or the Docker Compose
  deployment is the supported portable path where applicable.
- Packages and checksum files are not cryptographically signed yet.
