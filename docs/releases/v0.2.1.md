# itkView v0.2.1

This release makes the mirror hold what a module is actually made of, and puts
a component's record on one time axis.

## Assembled parts owned by another institute

- The component sync asked the PDB for components **owned by** or **located
  at** the institute. A module's parts routinely satisfy neither: on the
  reference mirror a half module owned by TUDO carries a hybrid owned by UT and
  a sensor owned by CERN, both standing at a third site. They fell through
  every scope — no local row, no assembly link, an empty module page with no
  pictures. **24 modules were empty for exactly this, hiding 64 parts.**
- A third pass now fetches the parts named in `children[]` that the listing did
  not return: **one request per missing part**, never per part, bounded by
  `sync_assembled_part_limit` (default 3000). A part the PDB refuses drops out
  of that run rather than failing the job — the listing is the sync's payload,
  this pass is enrichment, and the next run picks the part up.
- The prune pass cannot touch these rows: it only governs components owned by
  or located at the institute.

## A shape difference the fixtures could not show

Running the new pass against the production mirror exposed a second defect:
all 64 parts arrived **linked to nothing**. `parents[].component` carries the
parent's object id as a bare string from `listComponents`, but a *nested object
naming the serial* from `getComponent` — an id that appears in no batch, so
`id_to_sn` can never resolve it. Its `state` is `null` there too, which a check
for `!= "ready"` read as a dead link. Both shapes are read now, and a missing
state counts as live.

Measured against the reference mirror: **64 parts, 64 links, 24 module pages**
that finally show what they are made of; assembly links across a full run rise
from 1853 to 1917.

## The component history

- The detail page gains a **History** panel: stage transitions, mirrored test
  runs and relocations on one axis, newest first. Both of the first two were
  already mirrored — 8 662 stage events across 3 046 components — but the stage
  log fed only Statistics and the runs sat behind the worksheet, so the order
  of events had to be reconstructed by hand.
- The read model does not judge. A run the PDB has **retracted appears marked,
  not omitted**: the stage gate rightly ignores it, but a gap in a record is
  itself a claim. An undated legacy run sorts last and says it is undated
  rather than appearing at an invented date.
- **Relocations** join that axis. The PDB logs them in `locations[]` but names
  the site only by institution object id; `listInstitutions` resolves all 156
  in one request, so the log stays affordable. An entry whose site cannot be
  named is dropped rather than mirrored as a raw id — "moved to 5a84991d…" is
  not information.
- Timestamps are normalised to one UTC-naive reading, so the merge order does
  not depend on SQLite versus PostgreSQL.

## Known limitations

- The Windows installer is not code-signed, so Windows SmartScreen may warn.
- Three of the previously empty modules have no children in the PDB either;
  they are genuinely childless, not missing.
- The viewer still mirrors every measurement payload in full — 583 MB of 602
  on the reference mirror, 427 MB of it response curves. Reducing what is
  stored is deliberately **not** in this release: today's two defects both
  looked like a complete mirror and were not, and pruning raw data before that
  is settled would destroy the evidence needed to notice the next one.
- A component whose only pictures sit deeper than an assembled part's own
  parts still shows no tile.
