# itkView v0.1.0

This is the first dedicated itkView release: a fail-closed, read-only
viewer built from the itkFlow core without its production authoring and upload
surface.

## Highlights

- Browse mirrored components, families, required tests and production holds.
- Restore locally mirrored images and original run plots, including child
  component evidence and browser-safe handling of non-previewable image files.
- Show real array curves first and use generated plots only as a fallback when
  no original plot or usable array curve exists.
- Explore persistent, background-refreshed measurement statistics and
  configurable collective IV/CV curve views.
- Mirror supported public-share attachments, including bounded extraction of
  image files delivered inside CERNBox tar archives.
- Retry stale sync jobs safely, with lease fencing against late worker writes.
- Keep rotating local crash logs and export a bounded diagnostic bundle from
  packaged desktop installations.

## Read-only boundary

itkView has no Triage/Ingest screen, Staged/Outbox tab, watched-folder upload,
manual or file-based test entry, assembly, registration, stage move, PDB push,
shipment reception editing, reminder delivery or notification mutation.

The API enforces the same boundary for administrators and direct requests.
The PDB write scope, in-process processors, standalone worker, submitter and
direct registration sink are disabled. Authentication, local administration,
personal credentials and explicitly classified mirror-sync requests remain
available.

## Isolation and first start

itkView uses its own desktop application ID, cookies and
`%LOCALAPPDATA%\itkview` state. Its Compose deployment likewise owns a separate
project, `itkview` PostgreSQL database, attachment volume and encryption-key
context. It never opens or migrates an itkFlow database.

After installation, create the first local administrator, connect personal
PDB access codes under **Account**, then run a new mirror sync. Seeing fewer or
no components before that first sync is expected; itkFlow's mirror is not
shared.

## Known limitations

- This installer is not code-signed, so Windows SmartScreen may warn.
- Production reads require each person's valid Plus4U/PDB credentials. There
  is no deployment-wide credential fallback.
- Password-protected public shares can store a per-user share password.
  Private CERN account links still require CERN OAuth and are reported as
  skipped rather than prompting for or storing a CERN account password.
- A new installation must build its local image and plot mirror during the
  initial evidence sync; large mirrors can take time.
